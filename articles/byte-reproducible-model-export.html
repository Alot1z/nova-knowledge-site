Three bugs that made a verified export meaningless

The Hugging Face package for NOVA-s is six files and 1.85 MiB, and it exports with three gates: 27/27 tensors matched, max_abs_diff_vs_novacore = 0.0 on all six heads, agreement_with_novacore = 1.0. Those gates are real. Getting them to mean anything took three bugs, and each one failed in the same way — by looking completely healthy.

F20: the checkpoint that loaded random weights

NovaModel.trunk was a nested nn.Sequential, which produces keys like trunk.trunk.0.weight and trunk.trunk.0.bias instead of trunk.0.weight and trunk.0.bias.

from_pretrained does not raise on missing or unexpected keys by default. It loads what it recognises, warns about the rest, and returns a model whose untouched parameters keep their nn.Module initialisation. The result was a package that imported cleanly, returned the right shapes, produced plausible-looking logits, and was in fact an untrained network.

The fix is a bare nn.Sequential so the keys come out flat. The lesson is not about nesting — it is that a checkpoint format mismatch and a successful load are indistinguishable from the outside unless you compare outputs. The third gate, agreement_with_novacore = 1.0 across a real decide() call, is what caught it. Shape checks did not; from_pretrained returning did not.

F21: the verifier that verified nothing

verify() built its reference by calling model.state_dict() on the model it had just loaded and comparing the model against itself. Every tensor matched. Every difference was exactly zero. The gates passed on a package containing random weights.

This is worth dwelling on, because the failure mode is not stupidity — it is that a self-comparing test is structurally incapable of failing. diff = a - a is 0.0 for any a, including garbage.

The fix rebuilds the reference from the checkpoint file, read back through safetensors, independent of the loaded model. The second part matters: reconstructing the reference by reloading the same object would reintroduce the same circularity.

There is now a test that demonstrates the trap on purpose — it shows a self-referencing diff is trivially zero — so that anyone tempted to write the simple version again finds the counterexample in the test suite rather than in production. tests/test_verify_integrity.py parses the AST of verify() and fails if the reference is derived from the model's own state_dict. The invariant is enforced structurally, not by convention.

F22: the header that would not hold still

With the reference fixed, two exports of the same checkpoint produced different bytes.

The cause is in the format, not the exporter. safetensors builds its JSON header by iterating a Rust HashMap, whose iteration order varies between runs. Two tensors with the same names and same bytes can serialise with data_offsets in a different order, which changes the header, which changes the file hash.

Byte-reproducibility matters for more than tidiness. It is the only cheap way to answer "is the artifact I am shipping the artifact I built?" without a full numerical comparison, and it is what lets a downstream consumer verify a download against a hash instead of trusting a download.

The fix has two parts:

  1. Sort tensors by name before serialising.
  2. Rewrite the header to a canonical fixed point. data_offsets must be recomputed after

insertion shifts the byte layout, so the header is rewritten repeatedly — up to eight passes — until it stops changing, with 8-byte alignment and space padding. Eight is not arbitrary paranoia; it is the observed convergence bound for the tensor counts involved, and the loop exits on the first stable pass.

Every text artefact is also written with newline="\n", because a checkout on Windows will otherwise write CRLF and change every hash.

The result:

model.safetensors  sha256 5bcd0016ef533a3f8a34bdd67b1c2e2aa436868f2d408b63b0fc245ab0e7ad77
package            sha256 b65ebbce1354951b84cdd31e5161ac5c3bf86c8a6254fe7a416ef841e854c972

Re-exported from scratch in a native temp directory with nova absent from sys.path, and the committed blob hash equals the remote-downloaded hash.

The pattern

All three are the same shape: a check that cannot fail. A load that does not raise. A comparison against itself. A hash that nobody compared. Each passed, each reported success, and each would have shipped.

The defences that actually caught them were unglamorous:

  • Compare outputs, not shapes.
  • Build the reference from the bytes, not from the object under test.
  • Hash the artefact and diff the hash across runs.
  • Load the package in a fresh process with the source tree off sys.path — because "it works on my

machine with the repo installed" is a test that cannot fail either.

None of this is exotic. It is just the part of packaging that does not get skipped when the happy path is green.
