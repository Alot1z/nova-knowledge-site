Limit

This is a hand-built option set, so it measures something the headline accuracy does not: how the learned executive behaves when the options are not the ones it was trained on. The comparison lives in tools/selfhost_audit.py precisely because pimo/selfhost.py never imports pimo.world &mdash; the self-application must not see the answer key. Escalated decisions are recorded unlabelled, so they cannot leak back into the training set as successes.

This number moves when you install something

The option set is built by probing the machine, so the audit measures whatever is installed at the moment it runs. With the pimo-arbitrator skill present, <code>self:skill</code> becomes available and the distribution collapses to two surfaces &mdash; the model picks <code>self:skill</code> and <code>self:escalate</code> and nothing competes &mdash; so agreement reads 1.0000 over a binary choice. On a machine without the skill the same 192-scenario grid measures 0.8229, and every disagreement runs one way, towards escalation. Neither number is better than the other: they answer different questions because the option sets differ. A perfect score here is a signal that the test got easier, not that the model got better, which is why the audit&rsquo;s decision field says so out loud instead of printing a constant. Re-run <code>python tools/selfhost_audit.py</code> after installing or removing a surface, and treat the pick distribution <code>model_picks</code> as the thing to read alongside the agreement.
