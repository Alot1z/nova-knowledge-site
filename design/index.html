NOVA: Neural Option-and-Value Arbitration

Status. Implemented, measured, shipped. 145 tests green. Every number below is read from a file in experiments/; nothing is quoted from memory.

One sentence. NOVA is a learned arbiter that, given a 30-dimensional picture of what a machine is doing right now and an open-ended set of registered options, emits a scalar value for each option instance and picks the best one — without any fixed list of classes it is allowed to choose between.

1. The problem, stated precisely

An agent runtime accumulates capabilities: a cache lookup, a local 3B model, a deterministic function, an MCP tool, a sub-agent, a hosted endpoint, a human, an escalation path. The set is open. It changes while the program runs. A new MCP server appears; a local model is unloaded; a provider starts returning 503.

Two designs are common and both fail in the same place.

A classifier over fixed classes. Map the situation onto k labels — heavy, provider, rule — with a rule table or a small model, then look up which option belongs to each label. This is what the Jev kernel does: two booleans in, one of three fixed strings out, and confidence: 1 on every decision because a rule that fired cannot be unsure. It is fast, auditable and completely rigid. Add a class and you edit the vocabulary, retrain, and ship a new mapping table.

A hand-tuned scorer. Write down the conditions under which the cache is right, the conditions under which the online model is right, and the threshold at which you stop trusting the local one. This works until the conditions interact. cost_pressure only matters when budget_remaining is low; freshness_requirement only matters when query_volatility is high; escalation is right when several independent axes are wrong at once. Rule tables encode the axes you thought of and no others, and they degrade silently at the edges.

NOVA's claim is narrow and testable: a small model that reads the whole state vector at once beats both, because the interactions are learnable and the option set is not part of the model's output space.

2. Design invariants

These are the rules the rest of the document defends. They are enforced in code where possible.

  1. No fixed output vocabulary. No output layer is indexed by option identity. The value head

emits a scalar per option instance, computed from that option's own feature vector. Option identity enters only as features, never through an embedding table keyed by Option.id.

  1. Ground truth has one owner. All labels come from nova/world.py, an analytic world. The

model, the baselines and the bandits are statically forbidden from importing it; an AST-level test fails the build if they ever do.

  1. Availability is arithmetic, not opinion. An option is available when it is enabled and

availability["available"] > 0.5. Everything downstream reads that property.

  1. Novelty and uncertainty are different things. They get different heads. Folding them into

one score is the failure mode this design exists to avoid: a model that is confidently wrong about a novel state looks identical to a model that knows it is out of distribution.

  1. No network in the decision path. The decision model is local, deterministic given a

checkpoint, and makes no calls. The LLM surfaces it arbitrates over are somebody else's problem, and they are optional.

  1. Every number is measured or labelled a prior. Cost and latency are priors until a caller

feeds back real telemetry.

3. Contracts

3.1 Option

A capability that could act. Opaque id, free-form capabilities and requirements, six normalized dicts (cost, latency, risk, availability, quality, freshness, historical_success), a descriptive kind, and an open metadata mapping.

Option(
    id="esbuild:parse",
    description="TypeScript/JS bundler front end",
    capabilities=["parse", "bundle"],
    requirements=["node"],
    cost={"financial": 0.0, "token": 0.0, "energy": 0.01},
    latency={"p50": 0.15, "p95": 0.40},
    risk={"base": 0.05, "irreversible": 0.0},
    availability={"available": 1.0},
    quality={"self": 0.92, "ceiling": 0.99},
    kind="tool",
)

kind is a description for humans and for coarse feature flags. It is not an output class. Nothing in the decision path branches on it.

3.2 State

Thirty normalized floats in [0,1], grouped:

GroupFieldsWhat it encodes
Cacheexact_hit, sem_similarity, sem_agewhether a near-identical answer already exists
Freshnessquery_volatility, freshness_requirementhow fast the answer goes stale
Resourcesinternet, net_latency, local_model, tool, agent, loadwhat is actually reachable
Pressurebudget_remaining, cost_pressure, latency_pressurewhat it costs to be wrong about resources
Risktask_risk, blast_radius, verification_requiredwhat a bad outcome does
Task shapestep_count, ambiguity, complexity, novelty_prior, determinism_knownhow hard the work is
Historyrepeat_rate, recent_failure_rate, prior_success_rate, escalationswhat happened last time
Goalgoal_type, verification_weight, cost_sensitivity, latency_sensitivitywhat the caller says it cares about

cost_sensitivity and latency_sensitivity are derived in the feature projection rather than asked for directly, because a caller who reports cost_pressure and budget_remaining has already told you the sensitivity:

cost_sensitivity    = 0.5 * cost_pressure  + 0.5 * (1 - budget_remaining)
latency_sensitivity = 0.6 * latency_pressure + 0.4 * net_latency

This is the only arithmetic in the projection. Everything else is a clip.

3.3 Feature projection

STATE_DIM = 30, OPTION_DIM = 28. Both orders are canonical tuples — STATE_ORDER, OPTION_ORDER — read by the generator, the model, the baselines and the tests. A feature index means exactly one thing everywhere, which is what makes a head-to-head fair.

The option vector's last eight entries are coarse kind flags (is_cache, is_deterministic, is_local, is_tool, is_agent, is_online, is_human, is_escalate). They exist because option types genuinely correlate with value and the model should not have to rediscover that from 20 continuous numbers. They are inputs, never outputs.

4. Architecture

state (30) ──► state_enc: 30→256→256 ─────────────┐
                                                   │
option (28) ─► option_enc: 28→128→128 ──┐         │   shared across every option,
                                          ▼         ▼   so the encoder is permutation-equivariant
                          bilin_u(s) ⊙ bilin_v(o) / √r      rank-64 interaction block
                                          │
        concat[s ; o ; interaction] ──────┘
                    │
              trunk 384→512→256  (GELU)
                    │
   ┌────────┬────────┬─────────┬────────┬────────┬──────────┐
 value   cost    latency    risk     noise    novelty
   │        │        │         │        │        │
 the     aux.    aux.     aux.   uncertainty novelty (NOT
decision supervision ...          signal   uncertainty)

Four decisions in here are worth defending.

The option encoder is shared. One option_enc is applied to every option. The model therefore cannot memorize an option's position, and adding option #9 costs nothing in parameters. Permutation equivariance is structural, not regularized.

Interaction is a rank-64 block, not a scalar. The obvious shortcut is score = f(s) + g(o) plus a bilinear scalar sᵀWo. That collapses every interaction into one number, and one number cannot express "cost matters only when cost pressure is high, and separately risk matters only when blast radius is large". bilin_u(s) ⊙ bilin_v(o) / √r produces r learned directions; the trunk can then give each direction its own non-linearity.

The value head is per-instance. heads["value"] is Linear(prev, 1) applied to (B, N, prev). There is no Linear(prev, n_options) anywhere in the model.

Six heads, six jobs. value is the arbitration logit. cost, latency and risk are auxiliary regressions on the option's own expected cost, latency and risk — they force the shared trunk to represent those quantities instead of letting them vanish into the decision. noise regresses the squared probability error and is what feeds uncertainty. novelty regresses the state's novelty_prior and is what feeds the out-of-distribution check. Keeping them separate is what makes "I have never seen a state like this" distinguishable from "I am confident and wrong."

5. Decision

value = heads["value"](...)                    # (B, N) — one scalar per option
value = masked_fill(value, ~available, -1e9)  # unavailable options cannot be chosen
probs = softmax(value / temperature)
chosen = argmax(probs)
confidence = max(probs)

temperature = 0.10 was fitted on a held-out split by minimizing NLL, not guessed.

The -1e9 mask is applied by masked_logits, and every caller goes through it. An option with enabled = False is not "bad", it is not on the table; encoding that as a very negative logit instead of a filter means a disabled option cannot leak probability mass into the distribution and make every other option look less certain than it is.

Reason codes

The decision returns a structured result: selected_option, option_scores, confidence, plus per-head values for the chosen option. A natural-language reason is available and explicitly optional — the structured result is primary, because a reason string is the part most likely to be wrong and the part least likely to be read.

6. The cascade

Before the model runs, cheap deterministic stages get a chance:

  1. Exact cache hit. A byte-identical request with an answer already stored. No scoring.
  2. Semantic candidates. Near-neighbours above a similarity floor, with their ages.
  3. NOVA. Everything the cache cannot answer.
  4. Act. Execute the chosen option.

Each stage records telemetry, which is the only way a prior becomes an observation. A cache hit updates freshness and hit-rate; an executed option's latency updates the latency estimate; a failure updates historical_success. The registry is where this lives, and the SDK exposes it as record_outcome, record_latency, record_health.

This is the honest boundary of the whole project: an option's cost and latency are priors until a real caller feeds back measurements. Every "NOVA saves you X%" claim that cannot point at a populated telemetry store is guessing.

7. The context addon

NOVA scores options. It does not read, parse, summarize or compress text — there is no text model in it. Producing a smaller context is a different job, so it lives in a different module, nova/context.py, with its own measurement.

7.1 Constraints

  • Zero added parameters. The default executor is a deterministic planner, not a network.

"Small model size" is satisfied literally.

  • Stdlib only. A test asserts that importing nova.context pulls in no torch, no numpy, no

transformers. It works in a fresh clone on a machine with nothing installed.

  • Local and online, one interface. EndpointSummarizer speaks OpenAI

/chat/completions, which is what Ollama, llama.cpp's server, LM Studio, vLLM, OpenAI, OpenRouter, Together and Groq all expose. The URL decides which; the plan, the accounting and the report do not change.

  • The endpoint can only shrink. It is asked to rewrite the text the planner already

selected. It cannot widen the budget or resurrect dropped material.

7.2 The planner

Split each item into sentence-or-line units. Score every unit:

score = 3.0·norm(query_hits) + 2.4·[any query hit]      relevance, flat bonus on any hit
      + structural_bonus                                 paths, identifiers, error codes,
                                                         "must/never/required", questions
      + 0.6·recency                                      later material, gently
      + 0.8·framing                                      first and last units of each item
      + 6.0·pinned                                       pinned items are non-negotiable
      + 0.5·priority                                     caller-supplied
      + spread                                           do not spend the whole budget on one file

Query weights are IDF over the items being planned, so a term that appears in every file cannot dominate the score. Selection is greedy by score under a token budget; the rendered text is then reassembled in original order, because a plan that scrambles sentences is worse than no plan.

Every decision carries a reason string: query-or-structural-match, budget-selected, below-budget. An operator can audit why a line survived.

The per-item unit cap defaults to off, and when a caller sets one, the truncation is reported in plan.report()["warnings"]. An earlier version capped silently at 24 units per item; that made tokens_before describe a truncated view and turned every reduction ratio computed from it into a fiction. Finding that is finding F25 in the experiment log.

7.3 Measurement

python -m nova.compact_experiment plans ten reader-shaped queries over this repository's own docs and code at four budget fractions, and records the reduction, a retention probe, planning latency and peak traced memory.

The retention probe is the part that makes a savings claim checkable: probe terms are drawn from the corpus text, and the report says how many of them survived the plan. A reduction ratio with no retention number next to it is a number about nothing.

A query whose answer lives in one buried sentence is exactly where an LLM summarizer earns its cost — which is why EndpointSummarizer exists and why the experiment probes for a live endpoint and records what it found.

8. Training

Labels come from the analytic world. The teacher knows the value of every option in every state; the student sees the state and the options.

  • Value loss: cross-entropy over the teacher's argmax, plus a listwise term over the full

teacher score vector, so the model learns the ordering rather than only the winner. The ablation in EXP-002 measured the listwise term on its own at 0.90995 accuracy / 0.00255 regret / ECE 0.02436 — better accuracy than the shipped cross-entropy configuration, with marginally worse calibration.

  • Auxiliary heads: MSE on cost, latency, risk, noise and novelty against world labels.
  • Temperature is fitted after training, on held-out data, by minimizing NLL.
  • Unseen-template holdout: the evaluation includes option templates the model never saw in

training. This is the load-bearing test of the no-fixed-vocabulary invariant. Test accuracy on seen templates is 0.9005 with regret 0.0029; on unseen templates accuracy is 0.9101 with regret 0.0019. Accuracy does not degrade — it improves slightly — which is the signature of a model scoring by properties rather than by identity.

What the numbers do and do not say

NOVA wins on every metric on both splits: 0.9005 / 0.0029 on seen, 0.9101 / 0.0019 on unseen, against 0.2045 for the Jev-inspired rule table and 0.8246 for the best bandit.

They do not say NOVA will route your production agent 40% cheaper. Ground truth here is world-analytic-v1, an analytic world with a known value function. NOVA is a ranking model on that world, and the accuracy number measures ranking fidelity against a teacher, not task success in a deployment. The honest summary is: on a world with a known optimum, a 481k-parameter learned arbiter finds the optimum more reliably than eleven hand-built and learned alternatives, including online bandits that learn from the same stream it was trained on. Whether that transfers to a real traffic mix is an empirical question that requires production telemetry, which is exactly what record_outcome exists to collect.

One more limit worth stating: the size sweep's numbers (§4) and the head-to-head's numbers (§9) are from different runs with different fitted temperatures (s scored 0.8896 at T = 0.15 in the sweep, 0.9005 at T = 0.10 in the head-to-head). Compare within a table, not across them.

10. Calibration

Confidence is the model's own probability, so it has to mean something.

Temperature scaling, fitted on held-out data, lands at T = 0.10. Resulting ECE is 0.0230 on the test split and 0.0188 on unseen templates; false-confidence rate is 0.0291.

Two of the baselines are diagnostic rather than merely weak. jev_inspired and laya_inspired are rule systems: they run at T = 0.05 and report mean_confidence = 1.0, because a rule that fired has no distribution over the alternatives to be confident about. Their ECE therefore equals their false-confidence rate by construction — 0.7955 and 0.5362 respectively, each of them exactly its own error rate restated. A system that reports 100% confidence while being wrong 80% of the time cannot be calibrated, because it has no uncertainty model to calibrate.

The scored baselines (rule, keyword, cosine, linear) are a different story: they calibrate a temperature of 8.00, which flattens their distributions until ECE looks acceptable (0.085 to 0.415) while accuracy stays poor. Flattening is not the same as knowing. NOVA's ECE of 0.0230 comes with 0.9005 accuracy; theirs comes with 0.1280 to 0.6540.

11. Packaging

dist/nova-s-hf/ is a complete, self-contained Hugging Face model: config.json, configuration_nova.py, modeling_nova.py, model.safetensors, preprocessor_config.json, README.md. Six files, 1,942,077 bytes — 1.85 MiB. A consumer needs that directory and nothing else: no checkpoint, no dataset, no training run, no network.

Three properties are verified rather than asserted:

  • 27/27 tensors match the NovaCore checkpoint.
  • max_abs_diff_vs_novacore = 0.0 on all six heads; agreement_with_novacore = 1.0.
  • Byte-determinism. Exporting twice produces identical bytes:

model.safetensors sha256 5bcd0016…, package sha256 b65ebbce…. This needed work: the safetensors header is emitted from a hash map whose iteration order is not stable, so the exporter sorts tensors and rewrites the header to a canonical fixed point.

That last one exists because a verifier that compared a model against itself reported a difference of exactly 0.0 forever. The reference is now rebuilt from the checkpoint file via safetensors, and a test asserts that a self-referencing comparison is trivially zero — see findings F21 and F22.

One Hugging Face trap is worth recording: NovaModel.trunk must stay a bare nn.Sequential with trunk.0.weight-style keys. Wrapping it in one extra nn.Sequential produces plausible looking checkpoint keys that from_pretrained silently ignores, and the model then loads randomly initialized weights without raising. Finding F20.

12. Interfaces

from nova.sdk import Nova

nova = Nova.load()                       # artifacts/nova-s.pt
nova.register_options([
    {"id": "ripgrep", "kind": "tool", "capabilities": ["search"],
     "cost": {"financial": 0.0}, "latency": {"p50": 0.05}},
    {"id": "escalate:human", "kind": "escalate"},
])
decision = nova.decide(state={...})      # JSON-safe dict
nova.record_outcome("ripgrep", success=True)
print(nova.telemetry())

Registration rejects unknown option fields and a missing id rather than silently ignoring them, because a typo'd field in an MCP-provided option is the kind of thing that produces a decision which looks reasoned and is not.

Surfaces built on the SDK:

  • stdio MCP server — python -m nova.mcp_server, tools nova_decide, nova_discover,

nova_telemetry.

  • Hugging Face — the 1.85 MiB package above, loadable with transformers alone.
  • Context addon — python -m nova.context report --file X --budget 800.

13. Non-goals

Stated so that nobody has to infer them.

  • NOVA is not a language model. It does not generate text, parse text, summarize text or

embed text. Its inputs are 30 + 28 floats per option. Anything that reads text belongs in another component.

  • NOVA does not compact context. The cascade's cache stages avoid redundant work; the

context addon in §7 does the shrinking. Conflating them is how a router ends up making a savings claim nobody measured.

  • NOVA does not replace your agent loop. It picks one option per decision and hands back

telemetry. Planning, retries and verification stay where they are.

  • NOVA does not optimize tokens yet. Gate A11 stays open until end-to-end savings are

measured against production telemetry. The addon's §7.3 numbers are about a context planner, not about an agent's bill.

  • NOVA is not a general RL agent. It is a supervised arbiter distilled from an analytic

teacher. It does not explore, and it does not improve from its own decisions — it improves when a caller feeds outcomes back and the model is retrained.

14. Where this could go

  • Replace the analytic teacher with real traces the moment they exist. Every number in §9

would then describe a distribution nobody hand-designed.

  • Online adaptation. The bandits in EXP-007 are the natural comparison for this: NOVA beats

them statically, which means a properly adapted NOVA should beat them further.

  • Calibrated abstention. The noise head already produces an uncertainty signal; turning it

into a first-class "I don't know" that routes to a human is the obvious next behaviour, and the human and escalate option kinds are already registered for it.

  • Multi-step value. value currently scores the next action. Scoring a plan of options

needs a different label and a bigger world.
