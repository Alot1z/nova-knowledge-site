Why a fixed-class router loses to a per-instance scalar

The comparison that started this project was not against a neural network. It was against about forty lines of JavaScript.

Jev's kernel resolves a routing decision by evaluating two booleans and returning one of three fixed strings — heavy-reasoning, jev-provider, or rule — with confidence: 1 and reasonCode: "RULE_MATCH". That is a completely reasonable design for a router. It is fast, it is inspectable, and it never hallucinates a class that does not exist. Measured against NOVA's world, on the same features, in the same split:

A 0.20 accuracy is not a near miss. It is the accuracy of a system that is right one time in five, on a world where the right answer exists and is computable.

Where the loss actually happens

Three places, in order of severity.

The output space is closed. Two booleans partition into four regions. Three strings come out. Every option in the universe must land in one of three buckets, and the buckets are chosen by a human who has not yet seen the options. When the registry grows — a new MCP tool, a local embedding model, a second provider — the buckets do not grow with it. They get worse.

Interactions cannot be expressed. Cost pressure only matters when the budget is low. Freshness requirement only matters when queries are volatile. Escalation is right when several independent axes are wrong simultaneously and wrong when one is. A two-boolean rule table has no operator for "these two conditions together" except the one the author happened to write down. NOVA's low-rank bilinear block exists for exactly this: sᵀ(Vo) collapsed to one scalar cannot express "cost matters only when cost pressure is high, and separately risk matters only when blast radius is large". Sixty-four learned directions can.

Confidence is not a number, it is a constant. confidence: 1 is not a strong claim about the world; it is a statement that the code took a branch. The consequence is visible in the ECE column: 0.7955, which is exactly the system's own error rate restated as a calibration failure. You cannot calibrate it. There is no distribution over the alternatives to fit a temperature against. This is not a bug in the rule table — it is what a branch is.

What the fix costs

The fix is not "use a bigger model". It is changing what the model emits.

A classifier over k classes has k output neurons. Score every option and the output layer becomes Linear(hidden, n_options) — and that layer is keyed by option identity. The moment you register option #9, that layer is wrong and the model is retrained. You have rebuilt the fixed-class router with a matrix instead of an if.

NOVA instead emits one scalar per option instance, computed from that option's own 28-feature vector. There is no output layer keyed by identity anywhere in the model. Adding an option costs zero parameters. The load-bearing test is the unseen-template split, where the evaluation includes option templates that never appeared in training:

SplitAccuracyRegret
Seen templates0.90050.0029
Unseen templates0.91010.0019

Accuracy does not degrade. It improves slightly. That is the signature of a model scoring by properties — cost, latency, risk, quality, availability, capability match — rather than by identity. A model that had memorized which options are good would fall apart here.

What this does not prove

It does not prove a 481k-parameter model is the right choice for you. It proves that on a world with a computable optimum, learned per-instance scoring beats both hand-written rules and online bandits that get to learn from the same stream. Rule tables have a real advantage that this table does not show: they are readable by a human at 3am, they cannot drift, and they cost nothing to run. If your routing problem has three genuinely distinct regimes and you can name them, write the table. The moment the option registry becomes dynamic — which is the whole premise of an agent runtime — the table is a liability, because it cannot express an option you have not met.

The honest framing is narrower than "AI beats rules": when the candidate set is open and the conditions interact, a model that scores each candidate from its own properties generalizes to candidates it has never seen, and a model that classifies into fixed buckets does not.

The next question is the one every routing claim eventually has to answer: whose ground truth is this? NOVA's is an analytic world with a known value function, which makes the comparison clean and the absolute numbers meaningless in production. That boundary is documented in the design document, in finding F24, and on the About page of this site, because a comparison presented without its ground truth is an advertisement.
