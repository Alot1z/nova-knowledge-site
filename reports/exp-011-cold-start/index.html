PIMO's first decision is only useful if it arrives while the host is still waiting. Every other timing number in this project is measured inside a process that has already imported torch; this one is not. It spawns <code>python -m pimo.mcp_server</code>, speaks real newline-delimited JSON-RPC over pipes, and stops the clock when the first <code>pimo_decide</code> result comes back.

Why discovery left the decide path

It never belonged there. <code>run_discovery()</code> registers what it finds into the executive's registry, and exactly one caller reads that registry: <code>Cascade.handle</code>, the free-text branch, which unions it. <code>PIMO.decide</code> filters only the options in the request. So a caller that supplied its own options paid the whole discovery cost to populate a registry that could not change the answer. The host that wants the discovered pool calls <code>pimo_discover</code> and passes the results back in, which is what that tool is for.

Limit

Wall clock on one machine, not a distribution, and the budget is a gate rather than a guarantee: it is set roughly 4x above the measured cold start and roughly 3x below what the old path cost, so it catches a large regression and ignores machine noise. The warm decision is 0.005 s &mdash; the cold cost is import and checkpoint load, not the scoring.
